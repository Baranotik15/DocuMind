# TDD Constraints for Implementer Agents

When implementing code to pass tests (called from `/work` in TDD mode):

## Rules

- **DO NOT** modify test files
- If tests seem wrong, report back - don't "fix" them
- Write the **minimum** code needed to pass (but handle general case, not just test inputs)
- Follow patterns from relevant skills

## If Stuck After 2 Attempts

Report:
1. Which tests are failing and why
2. What approaches you tried
3. What specific blocker you hit

User will then choose:
- Provide implementation hints
- Adjust tests via test-writer
- Switch to Standard flow
- Skip this feature
